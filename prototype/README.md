# AI 期末试卷质量验证原型

这是一个用于验证“课程资料约束下，`deepseek-v4-flash` 能否生成可用高校纸质期末试题”的本地原型，不是生产系统。

它只保留一条最小闭环：上传暂存 → 整理并确认教学/考核大纲命题框架 → 在框架约束下整理教学材料 → 检查并发布候选知识点与证据 → 基础表单蓝图 → 按题型小批量生成候选试卷。每道题会展示答案、评分细则和它实际使用的来源证据，便于教师评估质量。

## 建议测试流程

1. 先在“大纲与命题依据”区一次选择并上传教学大纲、考核大纲；它们与教学材料分开保存。再在“教学材料”区一次选择并上传 PPT、PDF、DOCX、讲义或练习资料。支持 `.pdf`、`.docx`、`.pptx`、`.txt`、`.md`；暂不支持旧版 `.doc`、扫描 OCR 或图片理解。
2. 在“整理并确认命题框架”区域勾选教学大纲和考核大纲，点击“整理选中大纲”，检查模型提取的教学内容、考核要求、能力层级、排除项及其文件/页码依据后点击“确认命题框架”。原型仍用文件名或正文中的“教学大纲”“考核大纲”等线索确定大纲类型；无法识别时，请将名称或正文标注清楚。
3. 只有命题框架确认后，才能勾选教学材料区文件并点击“整理选中资料”。上传本身不会触发模型调用或进入 RAG；文件之间可并行整理，但同一模型请求不会混合不同文件内容。不能映射到已确认范围锚点的候选知识点会被排除，不能反向扩大考试范围。
4. 系统先剔除封面、姓名/学号/日期、提交与截图要求、孤立文件名、纯软件环境清单和只有步骤编号的操作标题，再将教学材料中的合格证据交给模型提取知识点。检查候选知识点、证据数量、框架范围排除提示与整理提示。
5. 点击“确认并发布候选知识库”，再填写考试总分、题型、题数、每题分值、范围和难度，构建蓝图。
6. 检查蓝图题位分配；点击“用 DeepSeek 生成候选卷”。系统按相同题型、每批最多三题调用模型，并对分值、答案字段、评分点总和和证据 ID 做确定性校验。
7. 展开每题的“答案、评分细则与依据”，由教师人工判断是否采用、修改或重新生成。

原型已实现最小的“大纲先行”框架：每份大纲独立调用模型提取可复核的教学内容、考核要求、能力层级和排除项，并以确认后的框架字段约束教学材料候选。它**尚未实现**生产级的双大纲语义冲突定位/解决、版本失效和 LangGraph 持久化；不能把它视为完整的 `FrameworkGraph`。

界面的默认示例为 100 分：15 道单选题、10 道判断题、10 道填空题、4 道简答题和 1 道综合题；教师可按课程实际需要改成任意合计正确、且分值为 0.5 分倍数的组合。

## 模型整理失败时如何查看原因

每次模型调用尝试都会追加一条本机 JSONL 诊断记录到 `.prototype-data/model-diagnostics.jsonl`。候选整理页也会显示最近的“模型诊断”。日志只保留模型名、请求字符数、HTTP 状态、请求 ID、`finish_reason`、`content`/`reasoning_content` 长度、令牌用量和脱敏错误摘要；**不会**保存 API 密钥、完整提示词或教学资料正文。

- `model_output_error` 且 `content=0`：服务端返回了 `choices`，但正式回答字段为空；结合 `finish_reason`、`reasoning` 长度和请求 ID 向接口提供方排查。
- `validation_error`：模型已经返回了文本，但不满足组织 JSON 格式（例如 `knowledge_points` 不是数组）；诊断会显示 JSON 顶层字段和该字段的实际类型。这是输出格式问题，不是网络问题。
- `network_error`：连接、超时或远端提前断开。先以一份文件、小批次复现；若集中发生在多文件并发时，可将 `.env` 的 `DEEPSEEK_ORGANIZE_CONCURRENCY` 暂时降低到 `2` 或 `4` 再比较。
- `http_error`：查看 HTTP 状态和请求 ID；常见于模型名、鉴权、网关兼容性或请求参数不被支持。
- `protocol_error`：HTTP 已成功，但响应不是兼容的 JSON 对象；诊断仅记录响应体长度和请求 ID，便于排查网关或接口兼容性。

## 质量验收清单

对每道生成题，至少检查：

- 考查范围是否可由展示的资料证据直接支持；
- 标准答案是否正确，选择题是否确有唯一最佳答案；
- 题干是否独立、明确、无歧义，且符合高校闭卷纸质考试语境；
- 难度、题型和分值是否符合蓝图；
- 主观题评分点是否覆盖题干要求且分值精确闭合；
- 同卷题目是否重复，或仅改写了练习题的表面措辞。

当前“通过”仅表示结构化规则检查通过，不代表语义质量已由系统保证；最终是否可用必须由任课教师确认。

## 数据与边界

原型的业务状态在内存中，服务重启后会清空。原始上传文件暂存在 `prototype/.prototype-data/uploads`，点击“重置原型”会同时清空内存状态和这批本地上传缓存。

资料整理和试卷生成会把当次小批量文本或单题最小证据包发送至 `.env` 指定的模型服务；不要上传无权发送给该服务的敏感内容。API 密钥只从本地服务端读取，不会发送给浏览器。整理阶段采用“宁缺毋滥”策略：模型异常或未输出可验证知识点时保留合格证据但不生成标题式回退候选，避免污染后续 RAG。

本原型不实现多课程隔离、数据库、`pgvector`、正式 LangGraph 持久化、权限审计、OCR、富文本编辑、Word/PDF 导出、异步队列或生产级文件安全扫描。正式设计基线见 `docs/superpowers/specs/2026-08-12-ai-final-exam-paper-design.md`。
