# 教师工作台前端设计方案

> 日期：2026-08-19
> 状态：设计已与用户确认（图谱+树双视图、横向流水线+单活动详情）
> 依据：产品设计基线 `2026-08-12-ai-final-exam-paper-design.md` §3.1/§3.2 + 当前项目现状（`CODE_WIKI.md`）+ 可视化线框图对齐
> 范围：教师工作台前端（课程空间 + 知识目录 + 试卷项目生产线），不含学生端

---

## 1. 背景与约束

### 1.1 现状

当前前端（`frontend/src/console/`）是 Vite + React 19 + TypeScript 的教师控制台骨架，含四步骤线性 wizard（资料→框架→知识→命题）与一个旧版 demo 查看器。设计系统为 minimal-dashboard（锌色中性 + `#2563ef` 单一蓝强调）。该前端当前仅为联调测试用，未正式设计。

### 1.2 心智模型纠正（关键）

现有"四步骤线性 wizard"混淆了两层对象，本方案予以拆分：

- **课程空间 = 长期可复用资产**（设计文档 §3.1）："资料只在课程空间上传一次，可用于不同年级、班级或学期的多次命题"。资料库 / 命题框架 / 知识目录是课程级资产，维护一次、永远复用。
- **试卷项目 = 按学期归档的命题对象**（设计文档 §3.2）：蓝图/合同/生成/审核/导出属于单次命题，"学年学期仅作为试卷项目的归档标签，例如 2026-2027-I 期末卷"。

因此"四步骤"被拆为两层：前三步（资料/框架/知识）= 课程级资产建设，第四步（命题）= 试卷项目内生产线。二者不可混在一根线性流程里。

### 1.3 设计目标

1. **符合人类操作**：贴近教师真实工作动线——平时维护课程资产、出卷时进项目做单次命题。
2. **不散乱**：每个对象有明确归宿，做事与看东西分离；同一屏内不堆叠多个无关模块。
3. **信息展示页**：知识目录的树/证据要能独立只读浏览，不与命题动作混在一起。
4. **高级感**：知识目录支持图谱式可视化，体现知识点关系。
5. **引擎层不动**：本方案只在工作台外层做服务与界面，`domain/generation`/`workflows`/整理链路内部机制不重构。

## 2. 整体信息架构（两层导航）

```
课程空间（首页与长期归宿）
├─ 资料库          ① 课程级资产：四区（教学大纲/考核大纲/教学资料/习题），上传一次、多次复用
├─ 命题框架        ① 课程级资产：双大纲→考点表，唯一 published
├─ 知识目录        ① 课程级资产 ★信息展示页：内容域/考核单元/知识卡↔证据，图谱+树双视图+证据中心
└─ 试卷项目（列表）→ 点入单个项目
     └─ 试卷项目内生产线：蓝图→合同→生成→审核→导出（5 阶段，只消费课程级知识目录，不复制资料）
```

- **顶层 = 课程空间首页**：4 个区块（3 个课程级资产 + 试卷项目列表）。
- **次级 = 试卷项目工作区**：进入后是 5 阶段生产线。
- 知识目录区块天然承担"信息展示页"职责（树/证据），既是维护入口也是只读浏览入口。

### 2.1 全局布局

- 左侧固定侧栏：课程切换 + 当前课程下的区块导航（资料库/命题框架/知识目录/试卷项目）。
- 顶部全局栏：面包屑、当前用户、健康状态（DeepSeek/MinerU 配置状态）。
- 主区：随左侧导航切换。

## 4. 知识目录模块（图谱+树双视图 + 证据中心）

### 4.1 页面结构

```
面包屑 + 标题 + status badge + [证据中心] [重新整理]
工具栏：搜索 | 筛选(簇/相关性/考点/状态) | [图谱|树]切换 | 布局下拉 | 导出
主区：左画布 + 右共享详情抽屉
状态栏：选中节点 + 未落地提示 + 统计
```

### 4.2 图谱+树双视图（同数据两种表达）

工具栏一键切换画布渲染，**切换瞬时、选中态与筛选保留**。右侧详情抽屉两视图共享（图谱点节点 / 树点卡 → 同一抽屉、同一详情）。

**图谱视图**：
- 力导向有机布局（SVG 节点+边，可缩放/拖拽/框选）。
- 节点：大椭圆=内容域、中椭圆=考核单元、小圆=知识卡。
- 节点大小=`importance`，颜色=`concept_cluster`（数据源 `knowledge_cards.concept_cluster`）。
- 边：实线箭头=`specializes`/`requires`/`component_of`，虚线=`contrasts_with`，粗线=`equivalent_to`（数据源 `relation_edges`）。
- 簇背景晕染圈住同 `concept_cluster` 卡。
- 默认折叠背景证据节点（只显 direct 卡），防节点爆炸。
- 大规模支持"按簇折叠成超节点"。
- 画布控件：缩放 +/-/复位、minimap、边类型过滤。

**树视图**：
- 层级树：内容域 → 考核单元 → 知识卡，可折叠搜索。
- 行尾原子落地计数：绿●=已落地 direct 证据数，红●=未落地。
- 大规模支持"按考核单元折叠"，与图谱折叠策略独立。

**统一未落地标红**：图谱=虚线红边节点，树=行尾红●+`needs_review`，与后端 `validate_publishable_tree` 对齐。

### 4.3 右侧共享详情抽屉

选中知识卡后显示：卡头（importance 星级、status、allowed 题型）+ 画像区（concept_cluster/answer_proposition/cognitive_targets/scope_boundary/performance_statement 彩色标签）+ 原子区（每条 `assessable_content` 带证据落地状态：绿✓已落地 / 红✕未落地→needs_review）+ 证据链区（direct/supporting 证据，来源页码、support、confidence）+ 关系区（relation_edges，点跳邻居节点）。底部"编辑/替换原子"。

### 4.4 证据中心（子标签 ②）

证据为中心、反向链到知识卡：
- 筛选栏：按资料文件 / 相关性（direct/supporting/background/out_of_scope）/ 考点 / 内容类型（content_kind）。
- 证据卡网格：每条含原文摘录、来源（文件+页码+标题路径）、confidence、content_kind、relevance 徽章（direct=绿/supporting=黄/background=灰）。
- "支持卡"chip 反向跳回知识树。
- 点证据→抽屉看原文全文+高亮对应原子。

### 4.5 两视图关系

知识树=正向（从卡看证据，命题可用性视角）；证据中心=反向（从证据看支持哪些卡，资料复用与覆盖视角）。同一证据双向 chip 跳转，避免散乱。颜色编码与后端 `RelevanceClass` 一致。

## 5. 试卷项目生产线模块（横向流水线 + 单活动详情）

### 5.1 入口

课程空间"试卷项目"区块 → 项目列表（按学期归档，显示状态/进度）→ 点击进入单个项目工作区。

### 5.2 工作区 Shell

- 顶栏：项目名 + 学期标签 + 状态 badge + 总分/题数/待处理数 + "基于知识目录 vN + 框架 vM"。
- **横向流水线**（全局概览，不平铺）：5 阶段圆点（① 蓝图 → ② 合同 → ③ 生成 → ④ 审核 → ⑤ 导出），渐变进度线连接，状态色编码（绿✓完成 / 蓝▶当前脉动放大 / 灰○虚线待解锁 / 红待处理计数）。
- 流水线下方标注两次确认闸门：闸门1=确认蓝图、闸门2=确认试卷版本；未通过则下游锁定。
- 点任一阶段圆点切换**下方单活动详情区**内容。
- 底部操作条：保存草稿 / 确认试卷版本→解锁导出。

### 5.3 五阶段详情

详情区一次只展一个阶段，点阶段圆点切换：

**① 蓝图**：题量分配预览表（章节×题型，最大余数法按 0.5 分单位）+ 难度/认知/模式分布 + `type_rules` 编辑 + 章节权重闭合校验 → 确认蓝图（闸门1）。

**② 合同（核心）**：题位算死表（#/题型/分值/难度/考点/知识卡·原子/答案域/综合原型，确定性分配零模型）+ 审计摘要徽章（quota_match / atom_uniqueness 37/37 / answer_mutex / 不冷门≥0.6 / 原型轮换8种）+ 换单题原子（`apply_slot_revisions`）+ 查看禁用上下文 → 确认合同→触发生成。

**③ 生成**：批并行进度（LangGraph Send API，≤6题/批，同考点同批，重试/换原子实时可见）+ model_call_count + 全卷终检五项报告（quota_match/atom_uniqueness/answer_mutex/traceability/needs_review，后者标红）+ 实时题目流查看。

**④ 审核**：三栏——左题目导航（37题，✓已审/!待处理标记）、中富文本编辑器（题干/分问/答案细则→阅卷JSON，工具栏 B/I/U/代码/列表/插图，含原子溯源）、右 needs_review 处理面板（按失败原因分类：换原子重生成/补细则）→ 确认试卷版本（闸门2）。

**⑤ 导出**：三卡同源一致——学生卷PDF（无答案/A-B卷/密封线）、答卷PDF（含答案+解析+评分点）、答案细则JSON（★阅卷端输入，校验 schema）。学生卷零答案泄露。

### 5.4 阶段切换规则

- 已完成阶段可自由回看（只读或可编辑，视阶段而定）。
- 当前活动阶段可编辑。
- 下游未到达阶段灰显，需上游闸门通过后解锁。

## 6. 设计系统与视觉规范（暗色苹果灰）

**视觉方向：苹果风 + 偏灰黑石墨底色**（用户确认，2026-08-19）。重写 `frontend/src/styles.css` 的 `:root` token 与结构类为暗色，复用 `frontend/src/console/ui.tsx` 原语（不改组件 API，只换底层 token）。

### 6.1 配色 token（暗色苹果灰）

- **底色/表面**（石墨近黑，层叠用透明白叠加而非实色）：`--bg #0a0b0d`、`--surface #1c1e22`、`--surface-subtle #141619`、玻璃卡 `rgba(255,255,255,0.04)` + 1px `rgba(255,255,255,0.07)` 边。
- **文字**：`--text #f5f5f7`、`--text-secondary #8e8e93`、`--text-muted #6b6b70`。
- **强调**（单一苹果系统蓝，暗色版）：`--accent #0a84ff`（主蓝）、`--accent-subtle rgba(10,132,255,0.18)`、`--accent-text #6eb5ff`。
- **状态色（暗色版成对）**：成功 `#30d158`、警示 `#ff9f0a`、错误 `#ff453a`、综合原型/评测簇 `#bf5af2`；各自配 `*-subtle`（约 15% 透明）与 `*-text` 浅化版。
- **相关性色编码**（与后端 `RelevanceClass` 一致）：direct=绿 `#30d158`、supporting=黄 `#ff9f0a`、background=灰 `#6b6b70`、out_of_scope=淡灰 `#3a3a3e`。

### 6.2 苹果风要点

- **毛玻璃**：`backdrop-filter: blur(20px)` + 半透明白边 1px + 表面层用透明白叠加。
- **大圆角**：卡片 16px、按钮/徽章 10px、徽章药丸 20px。
- **柔和阴影无硬边**：仅 `0 1px 0 rgba(255,255,255,0.04)` 内高光，无重投影。
- **排版**：SF/Inter 字体栈（`-apple-system, 'Inter', ...`），标题字距收紧 `letter-spacing: -0.01em`，正文 `line-height: 1.5`，充足留白。
- **克制单蓝强调**，不使用大渐变色；冷调无暖色。
- 当前活动元素脉动动画（流水线当前阶段、图谱选中节点）。

### 6.3 相关性色编码使用处

知识目录图谱/树的节点边、证据中心徽章、未落地标红（错误色 `#ff453a`，与后端 `validate_publishable_tree` 对齐）。

## 7. 与后端的对应关系

| 前端区块 | 后端 API / 数据 | 备注 |
|---|---|---|
| 资料库 | `materials.py`（upload-sessions/materials/parse） | 课程级，复用 |
| 命题框架 | `framework.py`（framework-runs/confirm/current） | 课程级唯一 published |
| 知识目录 | `knowledge.py`（organization-runs/publish/published-knowledge） | 图谱用 `relation_edges`+`concept_cluster` |
| 试卷项目列表 | 待建（`exam_projects` 表已存在 schema） | S2 试卷项目服务 |
| 蓝图/合同 | `blueprints.py`（allocate/confirm） | `PaperContract`+`ContractSlot` |
| 生成 | `generation.py`（generation-runs） | `build_generation_graph` 同步 |
| 审核/导出 | 待建（`paper_versions`/导出服务） | S2/S3 |

- 图谱/树的节点、边、画像字段直接取自 `knowledge_cards` 表（`concept_cluster`/`answer_proposition`/`prompt_material`/`relation_edges`/`instance_carriers` 等）。
- 证据中心取自 `evidence_chunks`+`knowledge_evidence_links`（relevance_class/content_kind/confidence/locator）。
- 未落地判定与后端 `validate_publishable_tree` 的 `fact_key_supported`/`all_facts_supported` 一致。

## 8. 演进路径

本方案分阶段交付（对齐 S1-S4）：

| 阶段 | 前端范围 | 依赖后端 |
|---|---|---|
| S1 | 课程空间首页 + 资料库/框架/知识目录只读浏览（图谱+树双视图、证据中心）+ 试卷项目列表骨架 | 生成链路正式 API 边界收口 |
| S2 | 试卷项目生产线（蓝图/合同/生成/审核富文本编辑、两次确认流、待处理清单） | PaperVersion 结构化内核 |
| S3 | 导出三卡（学生卷/答卷 PDF + 答案细则 JSON） | 导出服务 |
| S4 | 权限/审计/恢复硬化、27 条必测场景回归 | 验收 |

S1 优先交付知识目录的图谱+树双视图（用户最关心的信息展示页 + 高级感），以及试卷项目列表入口与生产线流水线骨架（详情区先占位）。

---

## 9. 验收标准

1. 课程空间四区块清晰分层，资料/框架/知识作为课程级资产可独立维护与浏览，不与单次命题混淆。
2. 知识目录支持图谱/树一键切换，切换瞬时保留选中与筛选；图谱体现 `relation_edges`/`concept_cluster`，未落地统一标红并与后端校验一致。
3. 证据中心反向链到知识卡，双向 chip 跳转不散乱。
4. 试卷项目生产线为横向流水线+单活动详情，不平铺；两次确认闸门显性化，下游锁定。
5. 符合 minimal-dashboard 设计系统，冷色调、无大渐变、卡片留白充足。
6. 真实数据（SK3020 课程，37 题/100 分）端到端可浏览可操作。
