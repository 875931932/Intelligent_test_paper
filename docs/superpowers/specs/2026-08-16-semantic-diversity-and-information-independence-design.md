# 全卷语义多样性与信息独立性设计

## 1. 目标

在不使用课程专属禁词、不限制某个固定产品名称、也不依赖生成提示词补丁的前提下，解决以下通用命题缺陷：

- 多张原子知识卡虽然标识不同，但实际围绕同一上位概念重复出题；
- 同一工具、人物、作品、案例、数据集或场景在全卷中过度集中；
- 前面一道或多道题提供的信息可以直接推出后题答案；
- 资料中某类内容较多，导致其知识卡数量反向覆盖考核大纲权重；
- 生成后才发现上述问题，造成不必要的整题或整卷重生成成本。

本设计把问题定义为“全卷语义覆盖与信息独立性”，而不是针对某门课程或某个具体名词建立过滤规则。

## 2. 设计原则

1. 考核大纲决定考试范围、权重和明确要求掌握的具体对象。
2. 教学资料只提供考点事实、实例和证据，不能凭资料数量提高考试权重。
3. 原子知识卡解决单题答案边界，语义概念簇解决全卷主题集中度，两者不能互相替代。
4. 具体实例默认只是通用知识的载体；只有考核大纲明确授权时，实例本身才获得独立命题权重。
5. 生成前优先阻止冲突，生成后只处理模型表达新增的信息泄露。
6. 任何集中度或泄露判断都依据结构关系和语义命题，不依据课程专属词表。

## 3. 知识组织层级

知识树增加原子知识卡之上的动态语义层：

```text
考纲内容域
  └─ 考核单元
      └─ 语义概念簇
          ├─ 原子知识卡
          ├─ 考查角度
          ├─ 答案命题
          └─ 实例载体
```

### 3.1 语义概念簇

`SemanticConceptCluster` 表示一组围绕同一可考核心能力或核心关系的原子知识卡。概念簇不是章节，也不是文件目录；它由卡片的可评分表现、答案命题和知识关系形成。

建议字段：

- `cluster_id`：内部稳定标识，不发送给生成模型；
- `exam_point_code`：所属考试考点；
- `title`：来源无关的概念名称；
- `assessment_goal`：该簇实际测量的能力；
- `card_ids`：所属原子知识卡；
- `importance`：由考纲要求与教师确认决定；
- `syllabus_authorization`：`explicit`、`implicit` 或 `none`；
- `relation_edges`：簇内原子命题之间的结构关系。

同一概念簇可以保存多张原子卡，但卡片数量不能转换为更多题位或分值。

### 3.2 答案命题

每张原子知识卡增加结构化 `answer_proposition`，表达该卡唯一允许考查的可评分结论。它区别于面向教师展示的卡片名称，也区别于最终题目的自然语言答案。

答案命题之间允许以下通用关系：

- `equivalent_to`：语义等价；
- `specializes`：下位命题；
- `component_of`：组成关系；
- `contrasts_with`：对比关系；
- `summarizes`：汇总结论可由若干子命题组合推出；
- `requires`：回答当前命题需要先知道另一命题。

这些关系由资料整理阶段形成，之后可被不同试卷复用，不需要每次生成重新推断。

### 3.3 实例载体

`InstanceCarrier` 表示用于承载通用知识的具体对象，包括但不限于工具、产品、框架、人物、作品、案例、数据集、机构和固定业务场景。

建议字段：

- `normalized_name`：规范名称；
- `carrier_type`：开放枚举式类别；
- `role`：`required_subject` 或 `illustrative_context`；
- `authorized_by_syllabus`：是否被考纲明确要求；
- `replaceability`：是否可以换成其他等价实例而不改变考核目标。

系统不维护具体名称黑名单。实例是否可重复由其角色、考纲授权和可替代性决定。

## 4. 资料整理流程

资料整理仍先按考点抽取原子可评分事实，然后增加一次来源无关的概念组织步骤：

```text
考点准入证据
  → 原子事实与原子知识卡
  → 提取答案命题
  → 建立命题关系
  → 聚合语义概念簇
  → 标记实例载体及其可替代性
  → 发布知识目录
```

聚合规则：

- 不按文件、页码、章节标题或来源数量建立概念簇；
- 不因为术语相同就强制合并，必须比较可评分表现与答案命题；
- 定义、条件、原因、结果和方案约束仍可保持不同原子卡；
- 如果多个子命题共同构成一个汇总结论，必须保存 `summarizes` 关系；
- 概念簇输出失败时不能退回“每张卡自成一簇”，应进入待确认或阻断蓝图，以免重新制造伪多样性。

## 5. 分层蓝图账本

蓝图分配顺序固定为：

```text
考纲目标分值
  → 考核单元分值
  → 概念簇选择
  → 实例载体曝光
  → 原子知识卡
  → 题型、难度和认知层级
```

采用词典序约束目标，而不是固定“某个名称最多出现几次”：

1. 精确满足题型分值和考纲内容域权重；
2. 满足每个题位的证据、题型和认知层级要求；
3. 最大化已使用的不同概念簇数量；
4. 最小化单一概念簇占用的题位数和分值；
5. 最小化未被考纲明确授权的实例载体曝光；
6. 最后才选择具体原子知识卡。

硬约束：

- 可执行蓝图不得重复 `card_id`；
- 存在兼容的未使用概念簇时，不得为独立客观题重复使用同一概念簇；
- 存在兼容的其他实例或无实例表达时，不得重复使用 `illustrative_context`；
- 综合题使用某实例后，必须计入全卷实例曝光账本；
- 资料多样性不足时，必须报告容量缺口，不能静默集中生成；
- 考纲明确授权的具体对象可以突破默认多样性顺序，但仍不能产生答案依赖冲突。

## 6. 全卷信息依赖图

生成前以题位为节点建立 `QuestionInformationGraph`。节点至少包含：

- `item_index`；
- `cluster_id`；
- `card_id`；
- `answer_proposition`；
- `required_propositions`；
- `instance_carriers`；
- `question_type` 和 `cognitive_level`。

图中检测四类冲突：

### 6.1 等价冲突

两道独立题目的答案命题等价，只是表达或题型不同。

### 6.2 单向蕴含

一道题公开的信息或答案命题可以直接推出另一题答案。

### 6.3 组合泄露

若若干题的题干、选项或答案命题组合后能够推出另一题答案，则建立多源依赖边。典型结构是两个组成命题共同推出一个比较或汇总结论。

### 6.4 线索泄露

最终生成文本中的题干、选项、材料、答案或评分点直接出现另一题的答案核心。

生成前必须阻止等价、单向蕴含和组合泄露。生成后审查只负责发现模型在自然语言表达中新增的线索泄露或偏离合同。

同一道综合题内部经过蓝图明确设计的递进分问可以共享前提，但每个分问仍需独立评分；不同独立题目默认不得形成答案依赖链。

## 7. 修复策略

修复顺序必须解决结构原因：

1. 换入同一考点下未使用的其他概念簇；
2. 在概念簇不变但不发生信息依赖的前提下换考查角度；
3. 换入其他实例载体或中性场景；
4. 重新分配该题位的原子知识卡和答案命题；
5. 资料容量不足时阻断并提示教师，而不是继续改写题干。

仅替换产品名称、增加禁词、调整措辞或要求模型“不要重复”均不属于有效结构修复。

## 8. 模型边界与成本

- 概念簇、答案命题关系和实例载体在资料发布时整理一次，可跨多次组卷复用；
- 全卷蓝图使用这些已发布结构，不重新向模型发送来源证据；
- 覆盖规划模型不得接收整卷大批题位；按固定小批次（当前原型为每批 4 个题位）分别规划，再由规则引擎合并并做全卷一致性校验；
- 规则引擎负责硬约束和账本校验，模型只承担难以确定的语义关系建议；
- 生成后仅对实际冲突题进行局部审查和修复。

## 9. 可观测性与教师界面

蓝图预览应展示：

- 各考纲内容域目标分值与实际分值；
- 每个概念簇的题位数、分值和题型；
- 具体实例载体的全卷曝光次数与分值；
- 因概念簇或实例集中度被替换的题位；
- 信息依赖冲突及冲突边类型；
- 资料多样性不足导致的最大可生成容量。

这些信息用于教师确认，不发送给最终题目生成模型。

## 10. 通用回归测试

测试不得使用课程专属过滤词作为通过条件，应覆盖多个领域：

- 两种网络协议属性与“二者差异”形成组合泄露；
- 两位历史人物事实与比较结论形成组合泄露；
- 化学过程的两个步骤与完整流程结论形成组合泄露；
- 多张卡引用同一统计工具但考查通用分析原则，验证实例集中度；
- 文学作品被考纲明确指定，验证考纲授权可以提高实例曝光；
- 只有一个概念簇有证据时，验证系统报告容量不足而非伪造多样性；
- 同一综合题内部合法递进、不同独立题目之间非法依赖。

验收条件：

- 章节和题型分值继续精确满足现有蓝图约束；
- 不同 `card_id` 但同概念簇的客观题不会在存在替代簇时被重复分配；
- 未授权实例不会因为资料和知识卡数量多而主导试卷；
- 组合命题可以识别“多题共同给出另一题答案”；
- 所有生成载荷继续保持来源无关；
- 修复只影响冲突题位，不整卷重生成。

## 11. 与现有设计的关系

本设计扩展而不推翻现有机制：

- 原子知识卡继续作为最小生成单位；
- 全卷卡片账本升级为卡片、概念簇和实例载体三层账本；
- 现有跨题答案审查升级为信息依赖图；
- 考核大纲权重、题型比例、难度分布和来源隔离规则保持不变；
- 现有 LangGraph 仍采用“蓝图确认—全卷规划—分题生成—终局审查—局部修复”流程。

## 12. 模型节点任务粒度与证据引用约束

真实链路验证补充以下不可回退约束：

- 一个资料整理模型调用只处理“一个考纲考点 + 一份教学资料”，不得把整门课或多个资料文件拼成一次事实抽取请求；
- 一个语义画像模型调用只处理一条已经展开的原子事实，不得让一个调用同时为大批事实决定概念簇、答案命题和实例载体；
- 一个题目生成模型调用只处理一个蓝图题位；全卷主脑只负责题位分配和覆盖计划，不负责批量书写多道题；
- 事实抽取模型不得生成证据 ID。输入证据在当前资料内使用短的 `evidence_index`，后端根据索引回填真实 `evidence_chunk_id`，以避免模型复制长 ID 时产生字符级错配；
- 一个事实返回多个 `assessable_content` 时，必须先展开为多个原子事实，再分别建立语义画像。不能把同一个 `answer_proposition` 复制到多个拆分后的原子卡，否则会制造虚假的等价答案冲突；
- `required_propositions` 表示认知前置关系，不等同于题干泄露。生成前硬阻断只针对等价答案、明确的组成命题汇总泄露和等价关系；题目自然语言新增的线索由终局文本审查处理；
- 每个模型节点的缓存键必须包含任务阶段、考点、资料或原子事实标识和输入摘要。局部失败只删除对应任务缓存，不得导致整门课程重新处理。

本轮真实验证结果：拆分后的资料事实、原子语义画像、蓝图、逐题生成和终局检查均完成；试卷 37 题、100 分，蓝图使用 37 张不同原子知识卡，生成文本未携带来源话术或资料中的具体部署工具名。

## 13. 能力族容量与覆盖规划批次（2026-08-16）

本轮真实卷暴露了一个与“模型是否听懂提示词”无关的结构问题：同一考纲考点内，原子卡数量很多，但其中若干卡属于同一上位能力族。若蓝图按原始卡数量估算资料容量，会把高分题优先分配给卡片多、但能力族单一的考点，最终形成大量同质题；若只按卡片唯一性选卡，也会在资料不足时把同一能力族铺满整类题型。

因此蓝图分配增加两项约束：

- 以“可用能力族数量”参与考纲考点的题位压力计算，而不是只看原子卡总数；能力族少而分值高的考点优先获得较高分值题位，减少低分客观题堆积；
- 在统一考纲权重求解时，同时把“可用原子卡数量”作为硬容量上限，任何考点的题位数不得超过可生成的独立原子卡数；无解时阻断蓝图，不静默复用答案核心。

这不是课程专属过滤规则，也不是限制某个词出现次数，而是把“能力族容量”和“原子卡容量”纳入通用的分值—题位联合求解。

覆盖规划同样拆小：每个模型任务只接收一个小批次题位（原型默认 4 个），批次之间通过已占用考查原子、答案边界和综合题结构键账本传递约束；批次完成后由规则引擎执行一次全卷闭合校验。逐题生成仍保持一个题位一次模型调用，终局审查只处理生成后的题目摘要和实际冲突。

本次回归结果：旧版前 1—5、8 题集中在角色/指令控制；修复后前 5 题先覆盖评估、配置、模型资产和 Benchmark，第 6、7 题才进入提示词角色相关内容；全卷 37 题、100 分、0 个卡片重复、0 个终局冲突、0 个来源话术命中。该分布结果作为后续跨学科试卷生成的结构回归夹具，不得通过课程专属禁词替代。
