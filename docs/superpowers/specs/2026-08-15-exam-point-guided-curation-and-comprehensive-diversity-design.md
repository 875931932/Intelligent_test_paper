# 考点驱动的资料整理与综合题多样化设计

**状态：** 已确认

**日期：** 2026-08-15

**适用范围：** 高校期末纸质试卷的资料整理、知识库发布、蓝图规划和综合题生成

**上位设计：** `2026-08-12-ai-final-exam-paper-design.md`、`2026-08-14-core-exam-system-development-design.md`

本文档是对既有核心设计的增量收紧，不替换课程空间、双大纲、MinerU、知识卡来源隔离、蓝图确认、全卷主脑、分题型生成和局部修复等既有设计。若旧文档中“先从全部教学资料自由提取知识点，再匹配大纲”的表述与本文冲突，以本文的“考试考点优先”链路为准。

## 1. 问题与根因

真实试卷验证暴露了三个同源问题：

1. 资料中的文件职责、配置项、接口路径和操作过程占据过多题位，整卷偏实践操作；
2. 综合题连续使用相似的“场景描述 + 固定数量分问”结构，题目原型缺乏变化；
3. 教学资料先被无目的地提取为大量知识点，考纲只承担宽泛范围匹配，导致知识点零散且资料数量反向影响考试内容。

根因不是缺少某门课程的过滤词，而是系统还没有形成稳定的权威方向：

```text
错误方向：教学资料里有什么 → 提取什么 → 尝试匹配考纲 → 分配题位

正确方向：考核大纲要求考什么 → 教学大纲校验教到什么程度
         → 为每个考试考点寻找课程证据 → 形成最小充分知识卡
         → 蓝图决定如何考
```

## 2. 目标与非目标

### 2.1 目标

- 考核大纲的期末考试范围、权重和能力要求成为考试考点的唯一准入来源；
- 教学大纲只校验已讲范围、教学深度和课程目标，不自行扩大期末考试范围；
- 教学资料只补充本课程的事实、原理、约束、案例和评分依据；
- 仅围绕考试考点检索和整理资料，不追求把全部资料转换成知识点；
- 操作细节是否可独立命题由考纲明确要求决定，不由其在资料中的出现频率决定；
- 蓝图显式控制理论、理解、应用、问题解决和实践操作的平衡；
- 综合题由全卷主脑分配不同原型、材料形式和认知任务；
- 所有教师可见来源仍可追溯，所有出题模型输入继续保持来源隔离。

### 2.2 非目标

- 不针对“大模型调优与部署技术”维护课程专属黑名单；
- 不删除解析结果中的文件名、页码和章节位置，这些信息仍用于教师追溯；
- 不让教学资料或模型常识补写考核大纲缺失的考试范围；
- 不让生成模型临时检索原始资料并自行判断考试范围；
- 不要求每门课程使用完全相同的理论/实践比例；
- 不在本设计中扩展图片、公式和图表的自动视觉命题能力。

## 3. 权威链与双门准入

正式权威链固定为：

```text
考核大纲：决定期末考试范围、权重、能力与明确操作要求
    ↓
教学大纲：验证是否讲授、讲授深度和课程目标
    ↓
教学资料：提供课程事实、原理、关系、约束、案例和评分依据
    ↓
纯净知识卡：向出题模型提供最小充分内容
```

职责边界不得倒置：考核大纲决定考试考点及其权重，教学大纲只辅助理解已教范围、深度和课程目标，教学资料与作业只补充受这些考点约束的知识证据。资料数量、作业题量或模型常识都不能反向创造考点、改变权重或扩大考试范围。

任何可出题知识必须同时通过：

- `scope_gate`：存在已确认的考核大纲考试考点，并通过教学大纲教学范围校验；
- `fact_gate`：存在当前有效教学资料中的直接证据，足以支撑答案和评分点。

考纲存在而资料证据不足时，系统报告缺口，不使用模型常识补齐。资料内容丰富但没有考试考点准入时，只能归为背景、辅助素材或超范围内容。

## 4. 考试考点模型

### 4.1 `ExamPoint`

`ExamPoint` 是考核大纲中可进入期末试卷的最小**考纲分配目标**，是 `FrameworkAnchor` 到 `AssessmentUnit` 之间的明确约束层。它不是资料章节标题，也不是模型从课件中自由归纳的知识点。既有 `AssessmentUnit` 仍然表示最小可评分命题目标：一个 `ExamPoint` 可以在资料证据支持下形成一个或多个 `AssessmentUnit`，但这些单元不得扩大 `ExamPoint` 的范围或自行获得新的考纲权重。

```json
{
  "exam_point_id": "ep_xxx",
  "framework_version_id": "fw_xxx",
  "content_domain_id": "domain_xxx",
  "title": "稳定、来源无关的考试考点名称",
  "assessment_requirement": "学生应完成的可观察表现",
  "weight_value": 15.0,
  "weight_source": "assessment_syllabus",
  "weight_group_id": "domain_xxx",
  "priority": "key",
  "cognitive_targets": ["understand", "apply", "analyze"],
  "assessment_orientations": ["conceptual", "problem_solving"],
  "allowed_question_types": ["single_choice", "short_answer", "comprehensive"],
  "operational_detail_policy": "supporting_only",
  "scope_boundary": {
    "include": ["应考内容和深度"],
    "exclude": ["不考内容和深度"]
  },
  "required_evidence_roles": ["fact_or_constraint", "answer_or_rubric_basis"],
  "retrieval_intent": "用于检索课程事实的语义描述",
  "assessment_anchor_ids": ["anchor_assessment_xxx"],
  "teaching_anchor_ids": ["anchor_teaching_xxx"],
  "status": "candidate"
}
```

`exam_point_id`、锚点 ID 和来源位置只用于业务关联、教师查看与审计，不能进入题目生成模型输入。

`weight_source` 只能是 `assessment_syllabus`、`inherited_group` 或 `teacher_confirmed`。持久化字段 `weight_value` 的领域单位统一为百分比百分点，`15.0` 表示 15%，`1.0` 表示 1%，`0.5` 表示 0.5%。解析适配器必须在持久化前根据显式的原始单位或考纲上下文把 `raw_weight` 规范化为百分点；若原始值 `0.15` 明确标记为 0—1 比例，才乘 100。持久化和容量计算阶段禁止再用 `<=1` 等启发式二次换算。只给出章节权重时，各 `ExamPoint` 继承同一个权重组，模型不得私自将章节权重平均拆分。组内分值由蓝图规划后交教师确认。

三层关系固定为：

```text
ExamPoint：考纲要求考什么、占多大范围、允许怎样考
  → AssessmentUnit：学生应完成什么可评分表现
    → KnowledgeCard：答案和评分点依赖哪些课程事实
```

### 4.2 操作细节政策

`operational_detail_policy` 采用三档：

| 值 | 含义 | 命题权限 |
|---|---|---|
| `forbidden` | 考纲没有操作类要求，或明确只考理论 | 文件名、命令、路径、安装步骤等不能进入知识卡或题目 |
| `supporting_only` | 操作内容有助于解释原理、构造案例或诊断问题 | 只能作为题干条件、辅助证据或问题场景，不能成为独立答案核心 |
| `directly_assessable` | 考纲明确要求配置、部署、操作机制或实践能力 | 可以形成知识卡和题目，但优先考作用、约束、取舍、诊断与解决问题，避免机械复现资料原句 |

该政策是跨学科准入规则，不依赖固定词表。诸如法条编号、实验器材型号、软件命令或会计表格字段，也按其是否被考纲明确要求以及是否支撑可评分表现来判断。

### 4.3 考点形成顺序

```text
考核大纲单文件解析
  → 定位期末考试栏目
  → 提取范围、章节权重、能力、题型和明确排除项
  → 构建候选 ExamPoint
  → 教学大纲单文件解析
  → 对齐已讲范围、教学深度和课程目标
  → 检查冲突、遗漏和权重闭合
  → 教师确认 framework_version 与 ExamPoint 目录
```

模型无法可靠拆分的宽泛考纲条目必须进入教师复核，不能在资料整理阶段由课件内容反向拆成新的考试范围。

## 5. 考点驱动的教学资料整理

### 5.1 暂存解析不产生知识点

教师主动选择教学资料并开始整理后，系统先执行：

```text
文件安全检查与哈希
  → MinerU/本地解析器提取结构化内容
  → 保存页码、幻灯片号、章节、表格和代码位置
  → 内容切块与去重
  → 建立本次运行专用的暂存关键词/向量索引
```

这个阶段只产生 `ContentBlock` 和暂存检索数据，不创建 `AssessmentUnit` 或 `KnowledgeCard`，也不发布到正式出题 RAG。

### 5.2 逐考点定向检索

系统为每个已确认 `ExamPoint` 构造检索意图，检索内容包括考点对象、认知动作、范围边界和所需证据角色，不包括来源话术。检索流程为：

```text
ExamPoint
  → 权限、课程、文件状态和框架版本过滤
  → 关键词 + 向量召回候选块
  → 语义重排序
  → 去除低相关候选
  → 按文件分组
  → 创建“一个 ExamPoint + 一个文件的少量候选块”模型任务
```

不同考点和文件任务可以并发。模型不得一次接收多个文件全文、整门课程资料或全部考试考点。

关键词、向量召回和语义重排都只是有界候选预选手段，不是知识准入依据。当前原型允许在没有嵌入服务时使用确定性词法预选；正式系统也不得把“全量资料全部向量化”当作解决范围污染、知识重复或资料数量偏置的根本方案。

### 5.3 相关性分类

模型对每个候选块输出以下分类之一：

| 分类 | 判定 | 后续用途 |
|---|---|---|
| `direct` | 能直接支撑该考点的事实、原理、关系、约束、答案或评分点 | 可参与提炼考核单元和知识卡 |
| `supporting` | 适合作为案例、数据、条件、错误现象或解释材料，但不能独立支撑答案核心 | 供教师查看或并入纯净卡片的题干素材字段，不单独形成考核单元或答案知识卡 |
| `background` | 主题相关，但对完成该考点的考核要求没有实质帮助 | 不进入正式命题索引 |
| `out_of_scope` | 超考纲、管理性、低质量、冲突或不安全内容 | 排除并保留原因供教师查看 |

成为 `direct` 必须同时满足：

1. 落在考点范围和教学深度内；
2. 能支撑明确的专业事实或评分判断；
3. 能帮助学生完成考点要求的认知动作；
4. 不是孤立标题、步骤、文件名、界面提示或任务要求；
5. 能定位回当前有效资料原文；
6. 符合该考点的操作细节政策。

主题相似不能代替直接支撑。同一大主题下与答案无关的片段必须归入 `background`。

### 5.4 模型输入与输出边界

资料分类模型可以接收：

- 单个 `ExamPoint` 的稳定名称、考核要求、认知目标和范围边界；
- 该考点的操作细节政策与所需证据角色；
- 一个文件中经过召回和重排的少量候选块；
- 文件名、页码、章节路径和内容块 ID，用于建立教师可见来源。

模型必须输出结构化 JSON，至少包含：

- `exam_point_id`；
- `content_block_id`；
- `relevance_class`；
- `support_claim`，说明它具体支撑什么；
- `evidence_role`；
- `candidate_assessment_unit`，仅在 `direct` 时允许；
- `candidate_card_content`，仅在 `direct` 时允许；
- `confidence` 与复核原因。

后端校验所有 ID 的课程、运行、文件和框架归属。来源字段与候选知识内容分字段保存。

资料整理层必须保留文件名、页码、章节路径、内容块和证据 ID，供教师查看、影响分析与审计；这些字段只存在于来源关系和教师视图。题目生成载荷必须由后端白名单重新编译，只包含纯净知识、题位约束、考查原子和答案边界，不得包含文件名、页码、章节、证据 ID 或其他来源话术。

`supporting` 原文和来源元数据不直接进入生成载荷。首期若需要使用其中的课程特定条件，必须先由整理模型提炼为来源无关的 `prompt_material`，与答案事实分字段保存并由教师确认；生成模型仍只读取当前题位的纯净卡片内容。

### 5.5 最小充分考核单元与知识卡

系统只从 `direct` 证据提炼 `AssessmentUnit` 及满足其命题需求的最小知识集合，包括：

- 核心定义和结论；
- 原理、因果关系和关键约束；
- 比较维度、适用条件和取舍；
- 常见问题、诊断依据和解决原则；
- 应用题所需条件、案例或数据；
- 标准答案和评分点需要的事实。

考核单元与知识卡都不追求覆盖资料全文。每张知识卡只能表达一个可独立命题、可独立判分的原子事实；定义与条件、原因与结果、方案与约束等不同答案核心必须拆成不同卡片，不能为了减少卡片数量把多个可命题事实塞进一张卡。同一条有效证据可以同时支撑多个原子知识卡，因此证据到知识卡是明确的一对多关系；反向看，一张知识卡也可以关联多条互相补强的证据。

相同或近义内容合并到已有单元/卡片并增加证据关联；证据已经充分后，高度重复材料不再创建新卡。每个 `AssessmentUnit` 必须属于一个已确认 `ExamPoint`，每张知识卡必须属于至少一个 `AssessmentUnit`。

考点权重还决定资料整理阶段的事实容量目标，避免低权重考点吸收过多卡片或高权重考点证据不足。当前原型建议：

```text
weight_percent = weight_value
target_card_capacity = max(4, min(20, ceil(weight_percent * 0.7)))
```

其中 `weight_percent` 直接读取已经规范化的持久化 `weight_value`，例如 15% 保存为 `15`，目标容量为 `ceil(15 × 0.7)=11`；1% 保存为 `1`，不会被再次放大。旧的比例输入必须在解析适配器边界通过明确单位转换，不能进入本公式后再猜测。上下限 `4/20` 与系数 `0.7` 是配置项，当前原型采用该默认值，正式系统可以根据课程证据密度校准，但不得退回“每个资料片段一张卡”。教师确认、证据不足和实际原子事实数量仍可使最终卡片数低于目标，模型不得为凑容量补造事实。

### 5.6 覆盖检查与教师确认

每个考试考点展示：

- 考纲权重和考核要求；
- 教学大纲对齐结果；
- 理论、应用与实践倾向；
- `direct`、`supporting`、`background` 和排除数量；
- 候选考核单元、纯净知识卡及可定位证据；
- 证据状态：`sufficient`、`insufficient`、`conflicting`；
- 资料缺口和需要教师决定的问题。

教师可确认、编辑、合并、拆分或排除考核单元与知识卡。只有已确认框架下、证据充分且教师发布的考核单元和知识卡才能进入正式出题索引。

## 6. 蓝图中的考查方式平衡

### 6.1 `assessment_mode`

每个 `PlanItem` 除题型、分值、难度、认知层级和知识卡外，增加：

| 值 | 含义 |
|---|---|
| `theory_recall` | 定义、术语、条件和基本结论 |
| `conceptual` | 原理、关系、原因和区别 |
| `application` | 在给定条件下运用知识 |
| `problem_solving` | 分析、诊断、决策、优化和解决问题 |
| `practical_operation` | 明确的配置、计算、实验或操作任务 |

蓝图同时满足章节权重、题型配额、题型内难度比例、认知层级和考查方式分布。资料数量不能影响考查方式配额。

卡片选择维护一份贯穿整张试卷的使用账本，题型节点只能读取并更新同一个全卷状态，禁止在切换选择、填空、简答或综合题时重置已使用卡片。高分题需要多张卡时，按各考点尚未满足的分值压力与可用原子卡容量分配；综合题可以在蓝图允许的范围内跨考点组合，但每个被组合考点都必须有明确考查原子、答案边界和分值归属。

考核大纲明确给出理论、应用或实践比例时直接采用；只给出能力要求而没有比例时，规划器根据认知目标和题型先生成建议分布，并在蓝图确认页展示依据和题数/分值结果，由教师确认。系统不得根据资料中文件类别或操作片段数量推导比例。

### 6.2 默认与教师调整

跨学科默认策略为：

- 选择、判断和填空以 `theory_recall`、`conceptual` 为主；其中填空题必须预留 `remember`/`understand` 认知层次，优先覆盖定义、术语、条件、基本结论等理论基础；
- 简答题覆盖 `conceptual`、`application` 和 `problem_solving`；
- 综合题以 `application`、`problem_solving` 为主，并可覆盖评价和设计；
- `practical_operation` 只能使用 `directly_assessable` 考点，其比例由考纲或教师确认的蓝图决定。

默认策略不是硬编码题型与认知层级的一一对应。教师可在蓝图确认前按课程特点调整，但系统必须显示调整后与考纲能力要求的偏差。

## 7. 综合题原型系统

### 7.1 原型目录

| 原型 | 核心任务 | 常见材料形式 |
|---|---|---|
| `case_analysis` | 阅读案例、材料或数据并解释关键现象 | 案例文本、数据摘要、条件表 |
| `fault_diagnosis` | 根据异常表现定位原因并提出修正 | 错误现象、日志摘要、错误步骤 |
| `comparative_decision` | 比较多个方案并在约束下作出选择 | 方案表、需求与限制清单 |
| `solution_design` | 根据目标和条件设计完整方案 | 任务目标、资源限制、验收标准 |
| `process_optimization` | 分析现有流程并提出优化措施 | 流程描述、瓶颈和指标 |
| `critique_correction` | 评价观点、答案、方案或过程并纠错 | 错误观点、错误方案、学生作答 |
| `integrated_explanation` | 串联多个相关原理解释复杂问题 | 复合现象、概念关系、因果链 |

课程不需要支持全部原型。主脑根据考点认知目标、知识卡内容、可用证据和分值筛选适合的原型。

### 7.2 主脑分配合同

`CoveragePlanner` 在分发题型节点前，为每道综合题增加：

```json
{
  "comprehensive_archetype": "comparative_decision",
  "material_form": "constraint_table",
  "cognitive_sequence": ["understand", "analyze", "evaluate"],
  "subquestion_count_range": [2, 4],
  "coverage_atoms": ["原子A", "原子B"],
  "answer_boundaries": ["答案核心A", "答案核心B"],
  "novelty_contract": "不得复用本卷其他综合题的场景结构和认知动作组合"
}
```

同卷存在多道综合题时：

- 优先分配不同原型；
- 不重复“原型 + 材料形式 + 认知动作组合”；
- 不重复答案核心或让一道题泄露另一道题答案；
- 分问数量由分值和任务决定为 2 至 4 问，不固定三问；
- 分问可以由基础理解递进到应用、分析、评价或设计，但不能套用唯一固定序列。
- 可以跨多个 `ExamPoint` 组合，但必须由考点分值压力、可用卡容量和认知链共同驱动，不能仅因为主题相近就拼接。

生成节点只能执行已分配的原型合同，不能退回通用“某公司/某团队 + 分别说明”模板。

### 7.3 跨卷结构新颖性

已确认综合题保存不含来源信息的 `QuestionStructureSignature`：

```text
原型 + 材料形式 + 主要认知动作 + 分问结构 + 答案边界摘要
```

生成新卷时，主脑默认读取同一课程最近 5 份已确认试卷的结构签名，用于降低结构重复；课程级配置可以缩小或扩大窗口。结构签名只参与规划与相似度检查，不把旧题全文、答案或来源发送给生成模型。

## 8. 工作流职责

### 8.1 `FrameworkGraph`

```text
parse_assessment_syllabus
  → extract_final_exam_rules
  → build_exam_point_inventory
  → parse_teaching_syllabus
  → align_teaching_scope_and_depth
  → validate_weights_and_conflicts
  → teacher_confirm_framework
```

它不读取教学资料，不创建知识卡，不使用资料补全考纲。

### 8.2 `OrganizationGraph`

```text
parse_selected_materials
  → build_staging_retrieval_index
  → schedule_exam_point_retrieval
  → classify_exam_point_evidence
  → distill_assessment_units_and_cards
  → consolidate_minimum_sufficient_units_and_cards
  → audit_exam_point_coverage
  → teacher_confirm_and_publish
```

LangGraph 负责编排、状态恢复、有限重试和人工确认。MinerU、切块、嵌入、召回和重排由普通任务执行器完成，不把正文写入图状态。

### 8.3 `GenerationGraph`

```text
allocate_blueprint_slots
  → allocate_assessment_modes
  → plan_unique_coverage_atoms
  → assign_comprehensive_archetypes
  → generate_by_question_type
  → cross_question_and_structure_audit
  → regenerate_only_conflicting_items
```

生成模型只接收当前题位的纯净知识、考查原子、答案边界、题型合同、考查方式和综合题原型；文件名、页码、证据 ID、考纲锚点和来源原文均不进入请求。

## 9. 失败处理

- 未识别到期末考试范围、权重或能力要求时显示缺失字段并要求教师确认，不用模型常识补全；
- 两份大纲冲突时保留双方原文位置并阻断相关考点确认；
- 某个考点没有足够 `direct` 证据时标记 `insufficient`，不得进入可执行题位；
- 单个“考点 + 文件”任务失败时只重试该任务，不重新整理全部资料；
- 模型返回空内容、非 JSON、JSON 顶层非对象或对象结构/Schema 校验失败时，都必须记录机器可读失败原因并执行有界重试；正式网关默认最多 4 次请求、按 1/2/4 秒退避（单次上限 8 秒），原型资料整理可配置为 2 次以控制成本。重试耗尽后进入待处理，不创建结构标题回退知识点，也不得复用该坏结果；
- 删除资料导致知识卡失去最小证据时，卡片标记失效并禁止用于新卷；
- 综合题原型缺少所需事实或材料时，主脑改选其他合适原型；不能强行生成无依据场景；
- 局部生成达到重试上限后进入终局确认；终局确认仍有疑点时保留 `needs_review`，不得伪装成通过。

跨题语义冲突的修复顺序固定为：先为冲突题换入全卷尚未使用且与冲突对象语义距离更远的原子卡；仍冲突时重新规划该题的考查原子与答案边界，再重新生成题目。只改题干措辞而保留原考查原子和答案核心不算有效修复。

宽松语义审查采用双审共识：两个相互独立的审查结果都认为存在冲突时才进入自动修复，避免单次宽松判断造成过度返工。达到修复上限后执行终局确认；既有冲突只有连续两次独立阴性确认才可清除，否则相关题位标记 `needs_review` 交教师复核，不能在修复次数耗尽时无条件升级人工。

演示快照在 Windows 上写入 `snapshot`/`pipeline.json` 时，必须先写同目录临时文件再原子替换；若目标文件被浏览器、杀毒软件或索引器瞬时占用，当前原型最多尝试 5 次，并按 50/100/200/400 毫秒退避。正式系统应把次数和退避基数配置化并记录最终原因，禁止无限循环或直接留下半写文件。

## 10. 可观测性

每次资料整理运行至少记录：

- 框架版本与考试考点数量；
- 每个考点的召回块数、重排保留数和文件分布；
- 四类相关性数量；
- 每个考点的直接证据、辅助证据、知识卡和覆盖状态；
- 模型调用次数、模型版本、耗时、token、重试和结构化错误；
- 被排除内容的原因统计；
- 教师编辑、确认和发布结果。

每次试卷生成至少记录题位的考查方式、综合题原型、结构签名、全卷冲突和局部修复原因。日志保存业务摘要和哈希，不默认保存完整教学资料或敏感提示词。

## 11. 回归测试与验收

### 11.1 必须具备的夹具

1. **实验资料噪声：** 文件名、路径、安装命令、步骤和截图要求在考纲未明确要求时不能形成独立知识卡或题目；
2. **考纲明确操作要求：** 明确要求配置或实践机制时允许命题，但考查作用、约束、诊断和问题解决；
3. **同主题低相关：** 与考点主题相似但不能支撑答案的资料块必须归为 `background`；
4. **资料数量偏置：** 实践资料远多于理论资料时，整卷考查方式仍按考纲和蓝图分配；
5. **综合题多样性：** 同卷多道综合题的原型、材料形式和认知动作组合必须有明显差异；
6. **跨卷相似度：** 新卷不能机械复用近期综合题结构签名；
7. **证据不足：** 考纲有考点但资料缺乏事实依据时必须报告缺口，不能生成无证据题；
8. **生成输入隔离：** 出题请求不包含文件名、页码、证据 ID、框架锚点或来源文本；
9. **大纲冲突：** 教学深度低于考核要求时必须进入教师复核，不能静默放行；
10. **局部失败：** 单文件、单考点和单综合题失败只能影响对应对象。
11. **原子知识卡：** 一张卡包含多个可独立命题事实时必须拆分；同一证据可关联多个拆分后的知识卡；
12. **全卷卡片账本：** 不同题型连续规划时已使用卡片状态不得重置，高分题按分值压力和剩余卡容量获得多卡；
13. **模型协议失败：** 空内容、非 JSON、非对象和结构失败分别留下原因，并在有界重试后进入待处理；
14. **语义冲突修复：** 先换未使用且语义更远的卡，再重规划考查原子和答案边界；仅改题干的修复必须判失败；
15. **双审与终局确认：** 宽松语义审查需要双审共识，修复耗尽后仅终局确认仍有疑点的题位进入教师复核；
16. **Windows 快照：** 模拟目标文件瞬时锁定，原子替换在有界重试后成功或留下明确失败，不产生半写 JSON。

### 11.2 验收标准

- 所有已发布 `AssessmentUnit` 都属于已确认 `ExamPoint`；所有已发布知识卡都能关联到已发布考核单元和至少一条有效 `direct` 证据；
- `background` 与 `out_of_scope` 内容不会进入出题索引；
- `forbidden` 与 `supporting_only` 考点不会生成以操作细节为独立答案核心的题目；
- 题位考查方式分布与教师确认蓝图一致，不随资料类别数量改变；
- 同卷综合题满足原型合同和结构差异要求；
- 出题载荷继续满足来源隔离白名单；
- 证据不足、模型失败和结构冲突均有明确状态，不存在静默兜底知识点。

## 12. 已确认决策

1. 采用“考核大纲定考点和权重、教学大纲校验、资料与作业补证据”的考点优先链路，不采用先提取全量资料知识再过滤；
2. 一张知识卡只承载一个可命题原子事实，同一证据可以支撑多张原子卡；
3. 权重决定可调的事实容量目标；权重先统一为百分比百分点，当前原型建议 `max(4, min(20, ceil(weight_percent * 0.7)))`；
4. 蓝图维护跨题型共享的全卷卡片账本，高分题按考点分值压力和可用卡容量分配，综合题允许受控跨考点；
5. 填空题预留 `remember`/`understand` 并偏理论基础，`assessment_mode` 和题型规则继续由教师确认；
6. 综合题由全卷主脑先分配原型、考查原子和答案边界，生成节点不得自行套用固定通用模板；
7. 模型协议/结构失败全部有界重试并记录原因，不接受空内容、非 JSON、非对象或坏结构静默兜底；
8. 跨题语义冲突先换未使用且语义更远的卡，再重规划考查原子和答案边界；宽松审查采用双审共识，修复上限后做终局确认；
9. 资料整理层保留完整来源供教师查看，生成模型只接收不含文件名、页码、章节、证据 ID 的纯净知识；
10. Windows 演示快照使用带瞬时文件锁有界重试的原子替换；
11. 不以课程专属禁词或全量向量化作为根本方案，操作准入、范围控制和重复防护由结构化权威链、原子卡与全卷规划解决。
