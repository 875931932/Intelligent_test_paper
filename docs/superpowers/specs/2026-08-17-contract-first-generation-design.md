# 试卷生成链路重构设计：合同优先（Contract-First）

日期：2026-08-17
状态：已与用户逐节确认，待最终审阅

## 1. 背景与根因诊断

### 1.1 现有链路

```
考纲 ──→ 框架图(framework_graph) ──→ 考点表(exam_points)
资料 ──→ 组织图(organization_graph) ──→ 知识目录(units/cards/atoms)
              │
              ▼
       蓝图分配(blueprint, 确定性) ──→ plan_items
              │
              ▼
       生成图(generation_graph):
         确定性原子初选 → 模型精排(N选1) → 按题型5路并行生成
         → 全卷审计(确定性+语义) → 修复循环 → 组卷
```

### 1.2 历次质量问题与补丁

| 问题 | 补丁 | 结果 |
|---|---|---|
| 考点重复 | atom 字面去重 → bigram 多样性排序 | 治了字面重复，治不了语义聚类（"SFTTrainer需要SFTConfig" vs "SFTTrainer需要数据集"） |
| 上下文抄写 | cross_answer_leak 字面检测 → 模型语义审计 | 检测越来越重，修复循环越绕越深 |
| 比例失衡 | 蓝图优先考纲权重 | 修好了，但知识树偏科又导致新问题 |
| 冷门题 | 原子核心度打分 | 阈值难调，仍有漏网 |

### 1.3 结构性根因（三个）

1. **全局约束靠事后兜底**：不重复、不抄袭、比例对、不冷门这些全卷级约束，全部依赖"生成后审计→修复循环"，而每次生成调用只看到自己那一题。
2. **分发维度错误**：按题型 5 路并行，同一考点的题分散到不同节点/调用，模型之间互不可见，重复必然发生；重复后再整体重生成，浪费资源。
3. **模型职责过多**：精排选原子、跨题协调、写题、审计都交给模型，每个环节都不可靠且都花钱。

### 1.4 已确认的设计决策

- 重构范围：保留框架图与组织图（前半链路基本可用），彻底重写蓝图分配+题目生成+审计段。
- 方案选型：合同优先（方案A），否决"命题总监评审模型"（方案B，成本翻倍治标不治本）与"四阶段全推倒"（方案C，风险大收益低）。
- 教师可在生成前审阅试卷合同并换单题原子。
- 单题重试上限 2 次。
- 成本默认配置：组织段批式分类开；模型语义终检默认关（教师可手动触发）。

## 2. 目标与成功标准

### 2.1 目标

根据教师上传的资料，按考纲的考点分布、比例、范围，生成高质量试卷。

### 2.2 成功标准（全部可自动验证）

| 维度 | 标准 | 验证方式 |
|---|---|---|
| 考点比例 | 每考点题数与考纲权重误差 ≤1 题（0.5步长配额） | 确定性断言 |
| 不重复 | 全卷 coverage_atom 唯一；同考点任意两题原子 bigram Jaccard < 0.5 | 确定性断言 |
| 不抄袭 | 任一题答案核心不出现在其他题的题干/选项中 | 确定性断言 |
| 不冷门 | 每题原子核心度 ≥ 阈值（池不足时显式报告教师，不静默降级） | 确定性断言 |
| 可溯源 | 每题携带 exam_point_id / unit_id / card_id / coverage_atom | schema 校验 |
| 成本 | 每次出卷模型调用 ≤ 考点批次数 + 失败重试数（40 题约 8~12 次） | model_calls 表统计 |

## 3. 链路总览（新）

```
考纲 ──→ [阶段1 考点表]   复用 framework_graph，强化：权重必填
资料 ──→ [阶段2 原子池]   复用 organization_graph，强化：答案边界必填；classify 改批式
              │
              ▼
       [阶段3 试卷合同]   ★全新·纯确定性·核心★
       配额→聚类→簇轮转→答案互斥→核心度门槛→结构轮换
              │
        （教师审阅合同，可换单题原子）
              ▼
       [阶段4 分批生成]   按考点分批（≤6题/批），批次并行
                          批内一次调用·同批互见·携带禁用上下文
              │
              ▼
       [阶段5 组卷终检]   确定性终检为主；模型语义终检默认关
```

## 4. 阶段 3：试卷合同（PaperContract）

### 4.1 定位

命题前把整卷"算死"：每个题位考哪个原子、答案域是什么、和谁互斥。全局约束在此**构造性保证**，而非事后检测。

### 4.2 输入

- 考点表（含 weight_value、allowed_question_types、cognitive_targets）
- 各考点原子池（knowledge_cards.assessable_content + answer_boundary + 核心度）
- 教师参数：总分、题型规则（数量/分值/难度分布）、章节权重覆盖（可选）

### 4.3 分配算法（六步，零模型调用）

1. **配额计算**：最大余数法（0.5 步长）按考纲权重算每考点题数；题型/难度分布按现有 blueprint 规则分配到考点内。权重和与总分校验失败 → 报冲突给教师。
2. **核心度门槛（池子预过滤）**：原子核心度 < 阈值的先剔除出池；过滤后池子不足以满足配额 → 生成显式冲突项（报告哪个考点缺多少可用原子），教师处理（放宽阈值/删考点/补资料），不静默降级。
3. **原子聚类**：过滤后的同考点原子按 bigram Jaccard > 0.5 聚成子主题簇（并查集）。
4. **簇轮转选取**：同考点多题跨簇取原子（轮转簇序），簇数 < 题数时才允许同簇第二原子（选簇内距离最远者）。
5. **答案域互斥**：候选原子的 answer_boundary 与已选原子的 answer_boundary 字面/包含重叠 → 跳过换下一个候选（簇内换，簇耗尽报冲突）。
6. **结构轮换**：综合题原型/材料形式/认知序列按轮换池取模分配，沿用现有 ARCHETYPE_CONTRACTS。

核心度阈值实施校准为 0.6（打分函数数学下限 0.45，原定 0.35 无过滤效果；0.6 使"非核心卡且无核心信号"的原子被剔除，核心卡/定义类关键词/绩效强调均可通过），已固化为常量 `DEFAULT_CENTRALITY_THRESHOLD`。

**真实数据实测补充（2026-08-18）**：真实课程资料产出的卡片大量落在 0.5~0.6 的"非核心卡但有部分信号"区间，默认门槛 0.6 在真实数据上过滤过强导致池不足；demo 链路按"显式非静默降级"原则（记录冲突→放宽至 0.5 重试一次→仍冲突则报错退出）跑通。后续迭代应基于真实卡片分布重新校准打分函数或默认门槛。

### 4.4 输出：PaperContract

每个题位（ContractSlot）：

```
{
  item_index, question_type, score, difficulty, cognitive_level,
  exam_point_id, unit_id, card_id,
  coverage_atom,            # 该题考的知识原子
  answer_boundary,          # 答案域
  forbidden_context: {      # 禁用上下文（该题生成时必须避开）
    atoms: [...],           # 同考点其他题位的原子文本
    answer_cores: [...]     # 同考点其他题位的答案核心
  },
  comprehensive_contract    # 仅综合题：原型/材料形式/认知序列/分问结构
}
```

加冲突项列表（配额无法满足、池不足等）与审计摘要（考点比例表、簇分布、难度分布）。

### 4.5 教师审阅

生成前展示合同：考点比例表 + 每题原子列表。教师可换单题原子（从该考点剩余候选中选）或直接确认。确认后进入阶段 4。（API 层面：allocate 返回合同 → 确认接口携带修订 → 触发生成。）

## 5. 阶段 4：分批生成

### 5.1 分批规则（纯算法）

- **按 exam_point_id 分批**：重复只发生在同考点内部，同考点必须同批。
- **批上限 6 题**：超限拆子批；子批载荷携带前批的禁用上下文（原子文本+答案核心），不携带原文。
- **小考点合并**：<3 题的考点与同章节考点合并成批，控制调用次数。

### 5.2 每批一次模型调用

载荷（source-free，沿用现有 payload 纪律）：

1. 该批全部题位的合同（原子、答案域、题型、认知层级——认知层级不同即视角不同）
2. 禁用上下文：同考点其他批次的答案核心
3. 指令：同批各题视角互补；禁用内容不得出现在任何题干/选项中

返回该批全部题目（JSON 数组）。

### 5.3 并行与重试

- **批次间并行**（LangGraph Send API）：互斥性由合同保证，批次互不依赖。
- **单题级确定性校验**（生成后立即，零模型）：schema 合法、答案命中答案域、禁用词未出现、题型规则（填空恰1空等）。沿用现有 validate_generated_question。
- **失败单题重试 ≤2 次**：带失败原因重新生成该题（作为同批小上下文补充调用）；仍失败 → 标记 needs_review 留给教师，不阻塞整卷。

### 5.4 删除项

| 删除 | 原因 |
|---|---|
| refine_atoms 模型精排节点 | 合同已把原子定死 |
| repair_conflicts 修复循环 + should_replan 路由 | 构造性保证替代事后修复 |
| 事后 semantic_clustering / cross_answer_leak 全卷检测 | 移到合同分配时构造性排除 |
| 按题型 5 路并行的固定节点 | 改为按考点批次的动态 Send |

保留：题型 schema 校验、综合题结构签名、溯源字段、model_calls 记录。

## 6. 阶段 5：组卷终检

- **确定性终检**（必跑，零模型）：配额 vs 考纲比例、原子唯一、答案互斥、难度/题型分布、每题溯源字段完整。
- **模型语义终检**（默认关）：教师手动触发，只出报告不驱动修复。
- 输出：试卷 + 审计报告（题 → 考点 → 原子 → 证据链）。

## 7. 成本设计

### 7.1 各阶段模型调用（40 题、7 考点、6 份资料）

| 阶段 | 现状 | 新设计 |
|---|---|---|
| 组织图 classify | 7×6=42 次 | **6 次**（批式：每资料一次，给全考点清单） |
| 生成精排 | 1 次 | 0 |
| 题目生成 | ~40 次 | **~7 次**（每考点批一次） |
| 修复重生成 | ~8 次 | ≤失败题数×2（通常 0~4） |
| 语义终检 | 1 次 | 默认 0 |

每课程一次性成本 ~51 → ~15 次；每次出卷 ~50 → ~8 次。

### 7.2 廉价替代原则

模型只做"写题"；语义相似用 bigram Jaccard、难度用关键词规则表、多样性用轮换取模、互斥用字符串包含、比例用最大余数法——全部确定性算法。

## 8. 数据与 API 变更

### 8.1 新增/修改领域对象

- `PaperContract` / `ContractSlot`（新，app/domain/generation/contract.py）
- 合同分配器（新，app/services/contract_service.py，替代并吸收现有 blueprint 分配中题位级的部分）
- `BatchGenerationPayload`（新，按批载荷）
- BlueprintRequest 语义微调：allocate 现在返回 PaperContract 而非裸 plan_items

### 8.2 API

- `POST /courses/{id}/blueprints/allocate` → 返回 PaperContract + conflicts + 审计摘要
- `POST /courses/{id}/blueprints/confirm` →（新）教师确认/修订合同
- `POST /courses/{id}/generation-runs` → 携带已确认合同；内部按批生成；同步返回试卷 + 终检报告

### 8.3 数据库

沿用现有表。paper_items 增加合同快照字段（或新增 contract_json 列）用于追溯。组织图批式分类改造 classify 调用结构，不改表。

## 9. 测试策略

- 合同分配器：纯函数，全量确定性单测（配额、簇轮转、互斥、门槛、轮换、池不足冲突）。
- 分批逻辑：纯函数单测（分批边界、子批禁用上下文、小考点合并）。
- 生成图：fake gateway 集成测试（批内互见载荷断言、单题重试、needs_review 路径、批次并行无交叉污染）。
- 终检：确定性断言全部成功标准。
- 成本：断言 model_calls 次数上限。

## 10. 实施顺序（供实施计划参考）

1. 合同领域模型 + 分配器（纯函数，先测起来）
2. 分批载荷 + 批式生成节点改造（generation_graph 重写为动态 Send）
3. 终检节点 + confirm API
4. 组织图批式分类改造
5. 删除旧路径（refine/repair/按题型节点）与旧测试适配
6. 端到端验证 + 生成新样例卷核对成功标准
