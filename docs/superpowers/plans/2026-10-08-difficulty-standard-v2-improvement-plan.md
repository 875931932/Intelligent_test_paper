# 难度标准改进方案 v2：先一致性 → 再可验证性 → 后实证校准

> 日期：2026-10-08
> 状态：**方案（本轮不修改代码）**，待负责人确认后分三轮实施
> 前置：`docs/superpowers/specs/2026-10-07-difficulty-feature-standard-design.md`（v1 设计——第一轮须同步修订其 §3.2 三档文义）
> 一句话：最值得改进的不是把标准写得更复杂，而是让系统能清楚回答——**这道题要求什么、实际检查了什么、哪些仍需要教师或真实作答验证。**

## 路线总览

| 轮次 | 主题 | 解决什么 |
|---|---|---|
| 第一轮 | 修正文义与输入边界（一致性） | 标准说什么 = 合同做什么；正式路径不把未知当通过 |
| 第二轮 | 可解释终检报告（可验证性） | 要求/检查/未知三者分层可见，教师确认进审核流程 |
| 第三轮 | 对照与校准（实证） | 用教师评价与真实作答证明改进有效 |

**明确不做**：不继续堆难度关键词；不一开始就引入难度预测模型；不扩在线考试/阅卷（范围红线）。

---

## 第一轮：修正文义与输入边界

### 1.1 单主原子口径统一（标准 × 合同的矛盾）

**现状（矛盾点）**：`difficulty_standard.py:56` `_FEATURE_TEXT` 中档写"双原子或同一概念的相邻知识"、
高档写"跨原子/跨章节多知识综合"；但合同 `ContractSlot.coverage_atom` 以**单主原子**为核心，
去重与答案域互斥也按单原子构造——文义与执行不一致，模型收到的规格和终检的抓手对不上。

**改法：暂时保留单主原子，不重构合同分配算法。** 三档定义调整为：

| 难度 | 修订后的操作定义 |
|---|---|
| 容易 | 围绕主原子，直接识别、解释或执行熟悉的基础操作 |
| 中等 | 围绕主原子，在常规变式中进行信息转换、应用或多步求解 |
| 困难 | 围绕主原子，在陌生情境中进行条件整合、方案选择或论证 |

- 核心认识：**难度可以通过任务要求与情境变化提升，不必强制增加考查原子数量。**
- 同步修订处：v1 设计文档 §3.2、`_FEATURE_TEXT` 文本（实施时）、作品方案 v5 对应章节措辞。
- **跨原子综合不在此轮做**：若后续确需，单独设计"主考查原子 + 辅助知识引用"，明确哪些知识
  参与判分、哪些只是背景，并重新验证去重与答案域约束；**禁止直接让模型自由跨原子出题**。

### 1.2 六段描述升级为按题型配置的可检查规格

**现状**：`difficulty_spec()`（`:92`）输出以文字为主（"2~3 步""陌生情境"），无法机器判定；
且不分题型——"困难必须 ≥4 步"对选择题与综合题不是一回事。

**待实现的字段结构（v2 规格，本轮仅定义）**：

| 字段 | 用途 |
|---|---|
| `target_cognitive_level` | 合同要求的认知层次（目标） |
| `allowed_knowledge_ids` | 允许引用的知识范围 |
| `reasoning_step_range` | 按题型配置的预期求解步骤范围 |
| `context_type` | 直接提问 / 教材变式 / 新情境…（枚举） |
| `information_operations` | 是否要求筛选、转换、整合条件（布尔/枚举） |
| `distractor_policy` | 选择题干扰项要求 |
| `standard_version` | 本题使用的标准版本 |

- **按题型分别配置**（单选/判断/填空/简答/综合各一份规格），先把**"什么算一步"**定义清楚
  （如：一次代入或一次同维比较 = 1 步；题干显式分问按问计——以题型规格文档为准）。
- **`standard_version` 随新合同冻结保存**：改标准只影响新合同，旧试卷仍能追溯当时依据，
  不原地改变历史合同（对齐"冻结即不可变"纪律）。

### 1.3 干扰项标准修订

- 删除容易档"干扰项与正确项明显异类"（`:63`）；不把困难档写成"选项越混淆越好"（`:77`）。
- 三档统一底线：

> 选项表述同质、错误项具有合理性、没有无意泄露答案的线索；难度差异主要通过所需知识和
> 辨析任务体现，而不是靠含糊或刁钻措辞。

### 1.4 正式路径严格校验（不把未知当通过）

**现状**：`canonical_difficulty()`（`:82`）无法识别即按 `medium`；`check_difficulty_fit()`（`:116`）
非低档直接 pass、认知层次缺失不触发拦截——这是为旧数据留的兼容入口，但正式合同路径目前
也走同一条道。

**改法**：兼容入口保留（AI 单题创建/改题/历史数据），**正式生成路径**（合同槽位 → 批量生成）
严格校验：

| 检查类型 | 处理 |
|---|---|
| 难度/认知枚举非法、合同字段缺失 | 正式路径**硬阻断**（不再静默默认 medium） |
| 引用合同明确禁止的知识、结构字段不满足 | **确定性阻断** |
| 疑似低档题要求复杂分析、疑似高档题仅直接回忆 | **风险提示**，必要时局部重生成 |
| 无法判断情境陌生度、推理复杂度 | 明确标记**"未自动验证"**，交教师复核 |

第一轮先落上两行（硬层），下两行随第二轮报告结构一起落地。

### 1.5 关键词检查改造（不再堆词）

- 从"任意位置包含词语"改为识别**任务表达**（"请分析""比较并说明""设计方案"等对学生提出的要求）；
- 术语豁免限定在**具体术语及其出现位置**，不再整道题全局豁免；
- 不能可靠判定 → 输出**风险**，不断言"难度不符"。
- 明确：本轮**不新增关键词表**，词表只做形态收敛（任务表达模式）。

### 1.6 封存边界

第一轮涉及 `validate_generated_question` 行为与可能的 `_check_question` 调用签名——
`generation_graph.py` 属**已验证封存**：先获负责人确认，改动后按项目要求跑**全量验证套件**，
不直接改。

## 第二轮：可解释的终检报告

### 2.1 四类数据分离（目标 ≠ 候选说明 ≠ 校验 ≠ 确认）

| 数据 | 来源 | 性质 |
|---|---|---|
| **目标特征** | 合同（`difficulty`/`cognitive_level` 盖章） | 权威要求 |
| **候选特征说明** | 生成模型自陈（求解过程、知识引用、特征依据） | **待核查说明**——"模型说三步"≠三步已证明 |
| **校验结果** | 确定性规则 | 检查了什么、发现了什么（已检查/有风险/未验证） |
| **教师确认结果** | 教师复核 | 最终认可，可追溯 |

- 现状：`cognitive_level` 只有"合同目标"一个语义（盖章进题，模型不输出）；"题目实际认知要求"
  没有独立字段——第二轮新增**候选自陈字段**与目标字段并列，不复用同一个字段。
- 原则：合同盖章不能代替内容判断，模型自陈不能当证据。

### 2.2 证据强度分层（完整口径）

| 检查类型 | 处理 |
|---|---|
| 难度或认知枚举非法、合同字段缺失 | 正式生成路径**阻断** |
| 引用了合同禁止的知识、结构字段不满足 | **确定性阻断** |
| 疑似难度与任务不匹配 | **风险提示**，必要时局部重生成 |
| 无法判定情境陌生度、推理复杂度 | 标记**"未自动验证"**，交教师复核 |

**重点不是让更多题"通过"，而是让"通过"的含义清楚。**

### 2.3 报告结构与接入点

- `validate_generated_question` / `check_difficulty_fit` 返回扩展为
  `{status, code, message, checks[], risks[], unverified[]}`——`status/message` 保持兼容
  （既有调用方只读这两个）。
- **风险** → 接入既有三道防线的单题重试链（≤2 次带反馈重出 = 局部重生成，不新开机制）；
  重试耗尽仍为风险 → 不阻断成卷，落报告交教师。
- **未验证** → 报告落库（持久化载体见开放问题 1），供教师端展示。
- 只增不改：不改变现有 blocker 语义。

### 2.4 教师端"难度依据"展开区（轻量，不新建页面）

```
目标：中等
要求：常规新情境、条件转换、应用
已检查：字段合法、知识引用范围
风险：候选解题过程可能只有直接回忆
未验证：实际作答难度
操作：确认 / 调整 / 局部重生成
```

- 挂在既有试卷阅读器题目详情处的折叠区；
- 教师修改题干、答案或选项后 → **重新检查，原确认标记置"待复核"**——难度控制进入审核流程；
- 确认结果落库可查（谁、何时、对哪版题目）。
- 前端改动 → 门禁 `npm run build` + `npm run lint`。

## 第三轮：小规模对照与校准（评估设计，非实验结果）

### 3.1 顺序：先教师内容评价，再真实作答校准

不需要扩展成在线考试或阅卷系统；真实作答用**线下测验 + 独立统计文件**。

### 3.2 A/B/C 三组对照

| 组 | 配置 |
|---|---|
| A | 只有难度标签 |
| B | 标签 + 六维任务规格 |
| C | 标签 + 六维规格 + 改进后的终检与反馈 |

- 固定：课程资料、题型分布、目标难度、模型配置、预算；
- 多轮生成，**教师盲评**（只见题面，不知组别）。

### 3.3 指标

1. 目标难度与教师判断的一致情况；
2. 各档题目的混淆矩阵（目标 vs 教师判断）；
3. 教师原样采纳率、修改时间；
4. 校验误拦截和漏拦截情况；
5. 重生成次数与调用成本。

### 3.4 真实作答后的实证指标

- 客观题正确率 / 题目平均得分率（CTT 难度系数 P 值口径）：**正确率越高，题目通常越容易**；
  "你觉得难不难"的问卷感受**不能替代**该指标（问卷仍保留，用于体验与过程数据）。
- 标签 vs 实测混淆矩阵 → 回灌修订规则阈值与认知配对。

### 3.5 范围红线

在线考试/阅卷仍是范围外需求，对照评估以线下测验与独立统计文件完成。

## 实施顺序与门禁

| 轮次 | 交付物 | 验证 |
|---|---|---|
| 第一轮 | 三档定义/干扰项底线/按题型规格（文档）+ 严格校验与任务表达识别（代码） | 终检逻辑改动必带单测 + 全量 pytest + 覆盖率 ≥80 |
| 第二轮 | 终检报告结构 + 风险/未验证分层 + 教师展开区 | pytest 全量 + `npm run build/lint`；涉封存 graph → 负责人确认 + 全量验证 |
| 第三轮 | 对照实验记录与结论 | 实验记录归档 `docs/superpowers/plans/` |

- 涉及封存的 `generation_graph.py`（`_check_question` 调用点）：**负责人确认 → 改动 → 全量验证**，缺一不可。
- 表结构变更只走 `app/db/schema.py` + `init_db` 幂等迁移（本项目无 Alembic）。

## 开放问题（实施前需拍板）

1. **报告存储**：`difficulty_report` 进 `generated_questions.payload`（免迁移、不可索引）还是
   独立列（可查询、需 init_db 迁移）？
2. **风险层是否自动局部重生成**：建议先"提示 + 人工确认"，第三轮误拦/漏拦数据齐了再开自动。
3. **目标认知字段命名**：复用既有 `cognitive_level`（合同目标）作 target，新增字段仅存"候选自陈"，
   避免双字段漂移——是否同意？
4. **`standard_version` 冻结载体**：合同级（整卷一份）还是槽位级（逐题）？建议合同级、槽位引用。
